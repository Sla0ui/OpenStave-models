# Verovio in OpenStave

OpenStave engraves and plays scores with [Verovio](https://github.com/rism-digital/verovio), which is
licensed under the GNU Lesser General Public License, version 3 (LGPL-3.0). This folder, together with the
source archive below, is the complete source of the Verovio build that OpenStave ships, including its one
change and the scripts that build it.

## What the app contains

| Part | Built from |
|---|---|
| `libverovio.so` | Verovio 6.3.0 with the change below, built as a separate shared library |
| `libverovio-jni.so` | The JNI glue SWIG generates from Verovio's `bindings/java/verovio.i` |
| Java classes `org.verovio.lib.*` | Generated by SWIG from the same file; kept with their names in the app |
| `assets/verovio/data` | Verovio's `data/` files, unchanged: `Leipzig*`, `Bravura*`, `text/`, `tuning-glyphnames.json` |

Each is built for `arm64-v8a` and `x86_64`.

## Source

- Upstream: <https://github.com/rism-digital/verovio>, tag `version-6.3.0`, commit
  `425dd7b6ba26edcecbe345c10b15586d095743d9`.
- The same source as an archive: `verovio-6.3.0.tar.gz` in this repository's
  [`verovio-6.3.0` release](https://github.com/Sla0ui/OpenStave-models/releases/tag/verovio-6.3.0).
- The change: [`expansionmap.patch`](expansionmap.patch). Verovio 6.3.0 crashes in `renderToMIDI` on two repeat
  ends with no repeat start between them (A :|| B :||). After each repeat end, the patched
  `ExpansionMap::GenerateExpansionFor` starts the next span at the following measure; other input expands as
  before.
- The build script: [`CMakeLists.txt`](CMakeLists.txt), as used by the app. It applies the change itself at
  configuration time, so give it the unpatched source; to build with Verovio's own scripts instead, apply the
  patch with `git apply expansionmap.patch`.

## Building

Tools: Android NDK 29.0.14206865, CMake 3.31.6, SWIG 4.5.0. Release builds use `RelWithDebInfo`, and the
symbols are stripped when the app is packaged.

```sh
tar xzf verovio-6.3.0.tar.gz      # or: git clone https://github.com/rism-digital/verovio && git -C verovio checkout version-6.3.0
SRC=$PWD/verovio-6.3.0

mkdir -p java/org/verovio/lib
swig -java -c++ -package org.verovio.lib -outdir java/org/verovio/lib -o verovio_wrap.cxx "$SRC/bindings/java/verovio.i"

cmake -S path/to/this/folder -B build -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE="$ANDROID_NDK/build/cmake/android.toolchain.cmake" \
  -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-26 -DANDROID_STL=c++_shared \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_CXX_FLAGS=-std=c++20 \
  -DVEROVIO_SOURCE_DIR="$SRC" -DSWIG_WRAP_FILE="$PWD/verovio_wrap.cxx"
cmake --build build
```

This gives `libverovio.so` and `libverovio-jni.so` in `build/`, and the Java classes in `java/`. The app loads
Verovio through these shared libraries, so a modified, interface-compatible build can take their place.
